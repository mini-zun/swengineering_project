첫 전체 실행은 124개 모두 통과했지만 SSR 검사 병렬 실행에서 포트 24678 충돌 로그가 있었다. 설치된 Vite 8의 구현을 확인한 결과 `hmr: false`만으로 WebSocket 서버가 꺼지지 않아, 모든 SSR/DOM 검사 서버에 `ws: false`도 적용했다. 수정 후 전체 124개 검사가 포트 충돌 로그 없이 통과했다. 제품 개발 서버 설정은 바꾸지 않았다. 통합 검사 작성 중 발생한 선택자 오류와 모의 치수가 테마의 높이 제한을 넘은 오류는 테스트를 수정했으며 제품 버그로 분류하지 않았다.

## 남은 수동 절차

1. 개인 자료가 없는 전용 Chrome/Edge 프로필을 준비한다. `frontend/`에서 `npm.cmd run dev -- --host 127.0.0.1 --port 5174 --strictPort`로 별도 origin을 실행한다. 포트가 사용 중이면 기존 서버를 종료하지 말고 빈 포트로 바꾸고 실제 주소를 기록한다. 이번 작업에서는 이 서버를 실행하지 않았다.
2. 실제 접속 주소, 검사한 커밋, 브라우저 정보 화면의 버전, viewport, 확대율을 기록한다. 공간 A/B에 `example.com` 링크, 서로 다른 할 일·여러 메모·문구, 공통 디데이를 넣는다. 공간 이름은 20자 이내의 긴 한글로, 할 일·메모는 허용 한도 안에서 긴 내용도 추가한다. 많은 공간 탭의 접근·스크롤도 확인한다. 사용자 origin의 저장소를 초기화하지 않는다.
3. 위 24개 셀과 좁은 화면에서 8개 영역의 잘림·겹침·필요한 스크롤, 여러 메모의 고정 위치·개별 크기, 위젯 전체 크기·최소/최대·드래그 중 공간 전환을 확인한다. 포인터 취소·Escape 및 키보드 방향키·Shift·초점 복귀도 실제로 조작한다.
4. 30방향 테마 전환과 A/B 왕복, 새로고침·새 탭 재접속을 실제 브라우저에서도 수행한다. 메모 보기의 테마 공통 범위와 공간별 위젯 크기를 혼동하지 않는다. 이름 변경·삭제 취소/확정·마지막 공간 제한과 새 공간 빈 상태를 확인한다.
5. 링크 추가·수정·새 탭 실행·삭제, 할 일 완료·미완료·삭제, 여러 메모 독립 편집·삭제·색상·개별 크기, 문구 저장·취소, 디데이 편집, 월간/주간 달력 조작을 확인한다. 한글 조합 중 Enter, 모달의 native inert 차단·Escape·Tab·초점 복귀도 남아 있다. jsdom에서 모달 뒤 버튼을 프로그래밍으로 누르는 것은 일반 사용자 경로로 인정하지 않는다.
6. 집중 재개·종료와 백그라운드 복귀·실제 경과 시간, 실행/정지 중 크기·공간 전환을 확인한다. 자동 검사는 세션 보존/복원 분기를 확인했지만 실제 절전·브라우저 종료의 시간 정확성을 측정하지 않았다.
7. 코르크 작은 글씨·시계 높이·종료 hover, 레트로 비선택 탭 hover/초점·테마 선택창 닫기, 포스트잇 목표 변경 hover/초점·집중 안내 summary 초점, 목표/복원 모달 팔레트를 확인한다. 정적 대비 검사의 통과는 실제 computed style과 모든 상호작용 상태의 통과가 아니다.
8. 실제 브라우저의 저장 실패 화면은 별도 테스트용 저장소 주입 환경에서만 확인한다. 현재 자동 검사의 실패 주입은 메모리 어댑터 전용이며 운영 UI에는 실패 버튼을 추가하지 않았다. 사용자 저장소를 채우거나 지워 실패를 만들지 않는다.

결과는 `브라우저 버전 / 주소 / 커밋 / viewport·확대율 / 시나리오 / 기대 결과 / 실제 결과 / 통과·실패·미검증 / 개인 자료 없는 증거 / 오류 이슈 링크`로 기록한다. 재현된 제품 오류가 생기면 관련 모듈·영향·재현 절차와 함께 연결한다. 현재 자동 검사에서 재현한 제품 오류는 없으며 실제 화면의 오류 유무는 미판정이다.
